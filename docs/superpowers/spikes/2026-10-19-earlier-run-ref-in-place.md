**Date:** 2026-10-19 · **Profile:** `ffroliva` (Flow served flow.google.com) · **Cost:** 5
images of daily quota, 0 Veo credits · **Probe:** `scripts/dev/spike_995_earlier_run_ref.py`
(readings pre-registered in its docstring, commit `addc5977`) · **e2e:**
`tests/features/earlier_run_ref_in_place.feature` bound by
`tests/e2e/test_earlier_run_ref_in_place_bdd.py`.

## Question

#913's in-place path (`MigratedComposer.reference_existing` →
`await_existing_references` → `attach_existing_references` → `_image_body_problem`) was
live-verified only for an image the same process generated a moment earlier. #995 / PR #996
infer that an image generated by an EARLIER process, in the same project, behaves the same.
Nobody had measured that.

## e2e result

`GFLOW_CLI_E2E_PROFILE=ffroliva uv run pytest -m e2e_image tests/e2e/test_earlier_run_ref_in_place_bdd.py`

- develop: `AssertionError: i2i of an earlier invocation's image in its own project failed on
  flow.google.com (exit 36)` · `1 failed in 57.24s`
- PR #996: `PASSED … attaches_it_in_place` · `1 passed in 87.13s`

The first develop run labelled the host "labs.google": host was read from the refused i2i,
which is refused at $0 before any `migrated.*` event. The step now reads the host from the
seed run (commit `3f8490a5`); the re-run above names it correctly.

The older `tests/e2e/test_image_uuid_ref_e2e.py` tests assert labs-only events
(`ui_automation_video.*`) and labs-only error text; on this host they cannot pass on either
tree. Left as they are — making them host-aware is more than a trivial change.

## PR #996 diff review (not a council)

- Claims hold: CLI `cli_image.py` call site passes the resolved `project.project_id`; MCP
  `_ref_meta_entry` writes `ref_meta[uuid].flow_project_id`, read back by
  `worker/codec.py::build_image_request` against `payload["project_id"]` — the key round trip
  is the same string on both ends. Labs never reads `in_project` (only set at
  `ui_automation.py:3121`). PR's focused tests: 26 passed on the PR tree.
- Nit (D14): `mcp/tools.py` `getattr(asset, "flow_project_id", None)` — `AssetLookup`
  declares the field (`data/models.py:221`); a plain attribute read suffices.
- Behaviour change to document: a same-project catalog row whose tile is gone now costs up
  to `EXISTING_REF_WAIT_S` (90 s) of reloads and exits 32, where it exited 36 at once. Both
  are $0; Q2 measured it at 4 loads with the wait lowered to 15 s.
